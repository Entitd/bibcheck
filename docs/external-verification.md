# Проверка источников

Первый этап: Crossref, Open Library, DataCite, DBLP. Дополнительный OpenAlex включается только с серверным ключом. Europe PMC и arXiv не включены.

Проверяется наличие публикации и согласованность метаданных, а не истинность научных выводов. Локальные проверки ГОСТ/кафедры независимы от внешнего результата. Отсутствие публикации в выбранных базах не доказывает, что источник вымышлен.

## Запуск

1. Настройте `.env` по `.env.example`: `QUEUE_CONNECTION=database`, `CACHE_STORE=database`. Укажите реальный служебный `BIBCHECK_CONTACT_EMAIL` при наличии; почта посетителя не используется. `OPENALEX_API_KEY` необязателен.
2. Примените миграции: `php artisan migrate --force`.
3. Обновите сборку: `npm ci && npm run build`.
4. Запустите постоянный воркер через свой systemd/Supervisor:

   ```sh
   php artisan queue:work --queue=external-checks --sleep=1 --timeout=90 --tries=0 --max-time=3600
   ```

   `retryUntil` каждого задания ограничивает его жизнь 30 минутами. Освобождение задания при занятом слоте не блокирует процесс. `retry_after` базы данных по умолчанию 150 секунд, TTL блокировки записи 120 секунд, TTL сетевой блокировки 20 секунд при timeout клиента 8 секунд.
5. Обеспечьте запуск Laravel scheduler (`php artisan schedule:run` раз в минуту). `bibliography:prune` завершает потерянные задания через 35 минут и удаляет детали завершённых запусков старше 30 дней; сохранённую историю сохраняет. Прежняя очистка гостевых пользователей продолжает работать. Failed jobs очищаются через 7 дней.
6. После изменения конфигурации: `php artisan config:cache` и `php artisan queue:restart`.

Воркеры всех пользователей должны использовать общие БД и cache store. `array` и `sync` годятся для тестов; для массовой проверки `sync` отклоняется сервером.

## API и совместимость

Сессионные маршруты под `auth`, CSRF и throttle:

- `POST /bibliography/external-checks` — `{bib_content, original_filename}`, ответ 202 `{data: {id, status, content_hash, finished_entries, total_entries, analysis}}`.
- `GET /bibliography/external-checks/{id}` — прогресс и анализ исходного снимка.
- `POST /bibliography/external-checks/{id}/cancel` — отмена. Чужой UUID даёт 404.

Гость — существующий пользователь гостевой сессии; отдельная внешняя регистрация не нужна. Повторная отправка идентичного текста повторно использует активный запуск. На одного владельца допускаются два активных запуска, до 100 записей и 100000 символов на файл. Повторяющиеся ключи BibLaTeX отклоняются.

`POST /api/sources/verify` сохраняет прежнюю структуру ответа, добавляя `schema_version=2`, статусы, проверки полей и диагностику провайдеров. Поддерживает необязательный `type`, `fields` либо одну запись в `text`/`file`; DOI/ISBN допускаются без title. API ограничен по IP и использует общий лимитер провайдеров.

`/api/bib/check-full` и `/api/bib/check-external` сохраняют синхронный ответ 200 для максимум трёх записей. Более крупный запрос получает явный 422 с адресом сессионного асинхронного маршрута. Проверка через кнопку редактора всегда фоновая.

Старые результаты без версии отображаются как исторический результат OpenAlex. Старый `found` не превращается в строгое `verified`. Совместимые метрики `api_found`, `api_not_found`, `api_errors` сохранены; `api_found` теперь считает только `verified`. В истории сохраняется версия анализа 2.

## Алгоритм и ограничения

DOI: Crossref → DataCite → OpenAlex с серверным ключом. ISBN/книги: Open Library; при отсутствии ISBN-результата возможен поиск по названию. Статьи/конференции без DOI: Crossref → OpenAlex с ключом → DBLP. Данные/ПО/диссертации/отчёты: DataCite → OpenAlex. Главы: Crossref. Для неподдерживаемых типов или недостаточных данных возвращается `not_checkable`.

DOI нормализуется без удаления внутренней пунктуации; ISBN-10/13 проверяется по контрольной сумме и приводится к ISBN-13. Названия сравниваются по тексту и пересечению слов; авторы — по фамилиям и совместимым именам/инициалам. Без идентификатора для `verified` нужны название, авторы, явное совпадение года и преимущество над вторым кандидатом. Порог названия 92 и разрыв 8 настраиваются в `config/bibliography.php`; это эвристики, не вероятности. Автоматической транслитерации нет. Неизвестные LaTeX-команды сохраняются; поддерживаются основные команды оформления и акценты.

Издание Open Library отличается от произведения: `first_publish_year` и ISBN всего произведения не подтверждают конкретное переиздание. Поиск загружает карточки до трёх предлагаемых изданий; без установленного издания результат частичный. При ISBN загружаются до четырёх карточек авторов, через тот же кеш и лимитер.

Годы online-first/печатного выпуска учитываются отдельно. Простой допуск ±1 не используется. Отсутствующие сведения имеют статус `unavailable`; противоречия — `different`. Сведения Crossref `created` не используются как год издания. Несколько баз могут использовать одинаковые исходные данные.

Отзыв независим от существования: `updated-by` с `type=retraction` у оригинала подтверждает отзыв; `update-to` у уведомления описывает другую работу. Исправление не считается отзывом. Наличие связи, источник, дата и URL уведомления сохраняются. Отсутствие связи отображается как «Сведений об отзыве не найдено».

Каждый реальный вызов, включая авторов, издания и повторы, расходует бюджет до шести запросов на запись. Счётчик атомарно резервируется в БД до отправки: остановка воркера не обнуляет бюджет. Слоты провайдеров общие для воркеров: один вызов одновременно и интервал одна секунда. DataCite дополнительно ограничен 450 вызовами за пять минут. Кеш предотвращает повторные сетевые вызовы; конкурентный запрос откладывается. Retry-After учитывается, временные ошибки повторяются с задержкой 5/15/60 секунд. Сбой, 429, повреждённый JSON, HTML вместо JSON и исчерпанный бюджет не считаются отсутствием источника.

Кеш метаданных по ID — до семи дней, поиска — сутки, HTTP 404 — шесть часов. Crossref ограничен сутками для актуальности признаков отзыва. Ключ поиска включает тип, название, авторов, год и версию алгоритма; результат сопоставления вычисляется заново. `fetched_at` сохраняет возраст метаданных, `checked_at` — время сравнения.

OpenAlex использует Bearer-ключ только из серверной конфигурации. Заголовки `X-RateLimit-Remaining` и `X-RateLimit-Reset` останавливают затратный поиск до сброса; дополнительно действует собственный предел 900 поисковых запросов в сутки UTC. Поиск остальных баз продолжается. Биллинг и платное пополнение не настраиваются.

## Проверки

Новые тесты: `php artisan test --filter='ExternalVerificationTest|ExternalCheckRunTest|ApiSourceTest|ApiBibValidationTest'`. Все сетевые ответы тестов подменяются `Http::fake()`; случайные реальные обращения запрещены. Проверяются идентификаторы, поля, неоднозначность, сбои, лимиты, кеш, авторизация, отмена, повторные задания, история и нагрузка 50 записей.

Пробные HTTPS-запросы 13 октября 2026: Crossref (включая направление связей отзыва), Open Library и DataCite вернули корректный JSON. DBLP с IP этого окружения вернул HTTP 202 и HTML-защиту от ботов. Код провайдера и обработка его JSON покрыты тестами, но реальная доступность DBLP с целевого сервера требует проверки. Защита не обходится; подобный ответ возвращает `incomplete`.

Пороги сопоставления проверены на небольших синтетических регрессионных случаях. Перед расширением применения оцените их на размеченном наборе реальных русскоязычных и международных библиографий. Проверка 50 записей выполнена также через настоящий database queue worker и database cache (50 завершений, 50 HTTP-вызовов, 0 failed jobs), с подменёнными API, без расходования квот; это не замер пропускной способности production.

Официальные источники: [Crossref REST API](https://github.com/CrossRef/rest-api-doc), [Retraction Watch](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/), [Open Library Search](https://openlibrary.org/dev/docs/api/search), [DataCite REST API](https://support.datacite.org/docs/rest-api), [DBLP API](https://dblp.org/faq/13501473.html), [OpenAlex authentication и квоты](https://help.openalex.org/api/authentication/).

Полный исходный набор тестов содержит пять прежних ошибок: четыре ссылки на отсутствующий `home` и ожидание 200 вместо существующего redirect `/dashboard`. Они воспроизведены на чистом HEAD в отдельной временной копии; к новой проверке не относятся.
